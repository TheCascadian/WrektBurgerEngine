# Security and modding trade-offs

Rule: C# modding is never disabled or crippled for security. Where security and modding conflicted, the network layer, authority model or sandbox changed instead. Real conflicts and the choices made:

| Conflict | Choice | Cost | Options not taken |
|---|---|---|---|
| Mods are code; running a peer's code is RCE | Code never travels. Mods are local; hashes are compared. | Players must install the same mods by hand; no auto-download | Auto-download of mods (needs signing and a trust store) |
| Mods want the full .NET API; the full API is an escape | Allow-list verifier on the compiled image, plus permissions in `mod.json` | Some APIs are missing (IO, net, reflection, threads, clock, `Random`). Mods needing them must use the engine API or `content` | Out-of-process mod host or WASM: stronger, much slower and a rewrite of the mod API. Not in this prototype |
| Trusted developer code (`backend/`) needs IO and environment | Backend tier is not sandboxed; it is locked project code, hashed at join | A malicious *project* is a malicious program. Install projects you trust | Sandbox the backend too (breaks existing backends) |
| Mod messages need to be flexible; flexible = injectable | Registered, typed schemas (Int range, Text length, Bool, Country); host validates, sender set by host | No free-form payloads | Raw byte payloads (fuzz surface) |
| Lockstep needs deterministic mods; `DateTime.Now`, `Random` break it | Those members are blocked in scripts; `Game.Rngs` is the supported source | Mod authors must follow the determinism rules | Trusting authors; the monthly checksum then resyncs |
| Mod `validate` (host) and `apply` (every machine) are reachable from network data; a loop in them hangs machines | Compiler-inserted step meter (`FuelRewriter`, `Fuel`): every function, loop, catch, finally and label ticks; `validate` and `apply` run with a step and memory budget on the calling thread; the stop cannot be caught; counted steps are deterministic, so `apply` stops at the same point everywhere; the message is then switched off. Replaces the abandoned-thread watchdog | A few percent slower mod loops; time inside one base-library call is not metered (bounded by its arguments); a recursion stop depends on stack size per machine (checksum resyncs) | Separate process with kill and CPU/memory limits (rewrites the mod API into messages, `docs/multiplayer/os-sandbox-evaluation.md`); cooperative cancellation by hand (mods could ignore it, and non-cooperation cannot be detected reliably at load); a collectible runtime (an unloadable context cannot stop a running thread either) |
| DTLS/UDP vs the existing TCP lockstep | TLS 1.3 on TCP (runtime), self-signed throw-away certificate, key confirmation with the join-code secret bound to the certificate hash (`docs/multiplayer/channel-spec.md`) | No NAT traversal, head-of-line blocking; the confirmation layer is custom and UNREVIEWED (small, specified, tested; first item of the external review) | The earlier custom ECDH/AES-GCM channel (replaced); TLS-PSK or exporters (not exposed by .NET); DTLS (no .NET support); QUIC (needs certificates and a relay) |
| Peer authentication without accounts | Session secret in the join code, or one expiring, revocable, single-use token per player (`Issue`, `Revoke`, `RotateSessionSecret`, `SessionSecretEnabled`) | The host hands out and tracks tokens by hand; identity is a host-chosen label, no accounts or long-term keys | Public keys per player and a ban list across sessions (needs an identity service) |
| Public P2P sessions (strangers, lobby) | Not built. Whether it is on the roadmap is OPEN (no stated plan); sessions are for players who share a join code. Sketch if it comes: each player holds a long-term Ed25519 key, identity = key fingerprint (optionally signed by an account service); the lobby or relay hands out short-lived tickets signed by the host key; the host keeps a persistent ban list by fingerprint; revocation = ticket expiry plus the ban list; the TLS key confirmation proves the player key instead of a shared secret; a relay hides the host IP | Until then: no strangers, the host IP is in the join code, bans last one session | Steam or platform accounts (ties the engine to a platform) |
| Host-authoritative vs cheating hosts | Clients validate shape and size, not game truth; a host save goes through a strict parser with limits and a schema before loading | A hostile host can still send false state or a valid but unfair world; a save above the warn level is loaded with a warning to the player; only one above the hard limits is refused (limits measured on late-game saves, `docs/multiplayer/multiplayer-security.md`) | Server-side dedicated hosting; signed saves |
| Out-of-process or OS sandbox for mods | Not done; verifier, permissions and a pruned API surface instead | A verifier bug or a hole in an allowed API is an escape | Process or WASM mod host: rewrite of the mod API into messages, breaks existing mods, hurts lockstep speed (`docs/multiplayer/os-sandbox-evaluation.md`) |
| Allowed API surface vs convenience | Removed what a mod does not need and what breaks determinism: time sources, `IntPtr`, SIMD, pools, URLs, weak references, culture state, `Type`/`Delegate`/`MemberInfo` reflection members | Mods that used `Vector<T>`, `Uri`, `TimeProvider` or culture state must change; common code (collections, LINQ, math, formatting with the invariant culture, `BigInteger`) keeps working | Keeping them and relying on the verifier alone |
| Float math across CPUs | Checksum + full-save resync | Cross-architecture sessions can resync often | Fixed-point sim (large rewrite) |
